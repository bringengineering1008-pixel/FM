# 브링이슈 발행 직전 매뉴얼 재확인 게이트 설계

## 목적

브링이슈 글을 예약발행하거나 즉시발행하기 직전에, 지금까지 사용자와 확정한 작성·시각자료·네이버 편집·검수 매뉴얼을 다시 읽고 원고와 대조한다. 기억이나 이전 검수 결과만으로 발행하지 않는다.

## 적용 범위

- 브링이슈 네이버 블로그의 신규 글, 수정 글, 예약발행, 즉시발행
- 외부 크롬 `rancemo858` 및 승인된 다른 브링이슈 발행 환경
- 동일 묶음에서 여러 글을 발행할 때도 글마다 발행 직전 대조 기록을 남긴다.

## 강제 게이트

발행 버튼을 누르기 전에 다음 자료를 현재 파일에서 다시 읽는다.

1. `docs/superpowers/specs/2026-08-26-bringissue-validated-40-40-20-content-design.md`
2. `docs/superpowers/specs/2026-08-27-bringissue-24-post-series-design.md`
3. `blog/templates/bringissue-action-guide-template.md`
4. 해당 게시물의 브리프·원고·이미지 원장
5. 현재 적용 중인 브링이슈 관련 추가 승인 매뉴얼과 사용자 지시

## 대조 항목

- 한 글이 질문 하나를 해결한다.
- 제목의 답이 도입 20% 안에 나온다.
- 공식 자료와 실제 화면이 결론을 직접 뒷받침한다.
- 실제 캡처의 핵심 글자가 모바일에서 잘리지 않고 읽힌다.
- AI·Flow 이미지는 공식 증거를 대체하지 않는다.
- 네이버 자체 표, 실제 구분선, 가운데 정렬과 의미 단위 여백을 적용한다.
- 형광펜·밑줄·이모티콘의 승인 범위를 지킨다.
- `그림 설명`, `영상의 몇 % 지점`, `확인 기준일`, URL 덤프를 노출하지 않는다.
- 개인정보·과장 주장·확인되지 않은 수치를 제거한다.
- 로그인 계정, 공개 상태, 검색 허용, 카테고리, 예약 시간을 확인한다.

## 실패 처리

한 항목이라도 불일치하거나 매뉴얼을 다시 읽었다는 근거가 없으면 발행 버튼을 누르지 않는다. 먼저 원고·이미지·서식을 수정하고, 다시 대조한 뒤에만 발행한다.

## 완료 기준

- `AGENTS.md`에 발행 직전 매뉴얼 재확인 규칙이 명시된다.
- 브링이슈 발행 전 체크리스트에 같은 게이트가 반영된다.
- 이후 발행 결과 보고에는 매뉴얼 재확인 여부와 불일치 수정 결과가 포함된다.
