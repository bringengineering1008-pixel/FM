# 브링이슈 행동 안내형 글 템플릿

생활·금융·건강검진·여행·디지털 문제 해결형 글에 사용한다. 사진 수나 소제목 수를 고정하지 않고, 독자가 실제로 판단하고 행동하는 데 필요한 만큼만 사용한다.

## 1. 제목 — 필수

`[대상 키워드] + [독자가 처한 문제] + [글에서 얻는 답]`

- 제목에서 약속한 질문은 도입 20% 안에 답한다.
- 과장된 결과·순위·수익·환급 보장은 금지한다.
- 반복 가능한 후속 글이 있을 때만 `[짧은 시리즈명]`을 제목 앞에 붙인다.
- 숫자는 연도·월·회차·금액·조건처럼 실제 판단에 필요한 경우에만 쓴다.
- 제목 이모지는 검색 의도를 방해하지 않을 때만 0~1개 사용한다.

## 2. 도입 — 필수

[독자가 실제로 검색창에 입력할 질문 또는 망설이는 장면]

[왜 헷갈리는지 1~2문장]

<mark>[한 문장 결론]</mark>

[글에서 확인할 내용과 독자가 얻게 될 결과]

- 도입과 한 문장 결론은 가운데 정렬할 수 있다.
- 회사 소개와 긴 배경 설명으로 시작하지 않는다.
- 도입은 `독자 장면 또는 질문 → 바로 필요한 결론 → 확인할 순서`의 세 박자로 구성한다.

- 이미지 역할은 `대표 / 근거 / 행동 / 비교 / 예외` 중 하나로 기록한다.
- 이미지 수는 고정하지 않는다. 역할이 없는 이미지는 빼고, 공식 화면의 단계가 더 필요하면 장수를 늘린다.
- AI·Google Flow 이미지는 대표·설명·비교 보조로만 쓰며 공식 사이트·앱 화면을 대체하지 않는다.

## 네이버 편집 규칙

- 도입은 가운데 정렬, 긴 설명·표·체크리스트는 왼쪽 정렬한다.
- 모바일 문단은 1~3문장과 한 의미 묶음을 기본으로 하고, 의미 전환마다 빈 문단 한 줄을 둔다.
- 한 문장이 모바일에서 길게 이어지지 않도록 한 문장당 1~2줄을 기본으로 한다. 주어·조건·결론이 한 줄에 겹치면 의미가 끊기는 지점에서 두 문장으로 나눈다.
- 번호형 본문은 `번호 소제목 → 빈 문단 1개 → 설명 문단 → 빈 문단 1개 → 체크 또는 인용구 → 빈 문단 1개 → 다음 번호 소제목` 순서를 사용한다.
- 단순 점 목록이 가운데 정렬된 문장과 분리되어 보이지 않게 한다. 선택 기준은 점과 문장이 같은 시작선에 붙는 목록으로 만들거나, 네이버 인용구 안의 체크 항목으로 바꾼다.
- 네이버 자체 구분선은 정보 블록 전환에만 기본 2개 안팎으로 사용하며, 짧은 글은 1개·긴 행동 안내형은 최대 4개까지 조정한다.
- 이모티콘은 본문 전체 1~3개를 기본으로 주요 소제목이나 전환에만 사용한다.
- 노란 형광펜은 결론·핵심 기준 2~3곳에만 사용한다.
- 밑줄은 행동 문장 2~3곳에만 사용한다.
- 한 문장에 형광펜과 밑줄을 동시에 쓰지 않는다.
- 문자 구분선, `그림 설명`, `영상의 몇 % 지점` 문구를 금지한다.
- 표는 동일 기준으로 둘 이상의 선택지를 비교할 때만 사용한다.
- 인용구는 핵심 판단 한 문장에만 0~1개 사용한다.
- 공식 링크와 다음 질문에 답하는 관련 글은 각각 필요한 1~2개만 연결하고 URL 목록을 덤프하지 않는다.

### 네이버 편집기 입력값

| 요소 | 기본 입력값 | 예외와 용도 |
|---|---|---|
| 제목 | 제목 입력란 기본 서식 | 검색어를 앞쪽에 두고 이모지는 필요할 때만 0~1개 |
| 도입·일반 본문 | 나눔고딕 19, 줄간격 180%, 가운데 정렬 | 긴 목록·표·조건 비교는 왼쪽 정렬 |
| 주요 소제목 | 나눔고딕 24, 굵게, 가운데 정렬 | 소제목 이모지는 글 전체 1~3개 안에서만 사용 |
| 보조 소제목 | 나눔고딕 19, 굵게 | 단계 안의 작은 구분에만 사용 |
| 핵심 인용구 | 나눔고딕 19, 굵게, 네이버 인용구 컴포넌트 | 글 전체 0~1회, 결론이나 판단 전환에만 사용 |
| 사진 캡션 | 나눔고딕 15, 회색, 가운데 정렬 | 화면에 실제로 보이는 사실과 볼 위치를 설명 |
| 표 본문 | 나눔고딕 16, 왼쪽 정렬 | 짧은 숫자·상태 열만 가운데 정렬 |
| 링크 | 설명 문장 뒤 네이버 링크 카드 | URL 원문을 본문에 길게 노출하지 않음 |

### 빈칸과 요소 간격

- 같은 의미를 이어가는 1~3문장은 한 문단으로 묶는다.
- 의미 묶음이 끝나면 네이버 편집기 빈 문단을 정확히 1개 넣는다.
- 주요 소제목 앞에는 빈 문단 1개, 소제목 뒤에는 빈 문단 1개를 둔다.
- 네이버 자체 구분선 앞뒤에는 각각 빈 문단 1개를 둔다.
- 사진 앞에는 빈 문단 1개를 두고, 사진 바로 아래에 캡션을 붙인 뒤 빈 문단 1개를 둔다.
- 표 앞뒤에는 각각 빈 문단 1개를 둔다.
- 인용구 앞뒤에는 각각 빈 문단 1개를 둔다.
- 링크는 해당 링크가 필요한 이유를 설명한 문단 바로 다음에 넣고, 링크 뒤에는 빈 문단 1개를 둔다.
- 빈 문단을 2개 이상 연속으로 넣어 큰 공백을 만들지 않는다.

### 대표 썸네일

- 글마다 현재 주제에 맞춘 가로형 대표 썸네일 1장을 제작해 제목 바로 아래, 도입 문단보다 먼저 배치한다.
- 썸네일 문구는 핵심 검색어와 독자의 질문을 큰 글자 1~2줄로만 표시한다.
- 작은 설명문·표·많은 아이콘을 넣지 않고 모바일 목록에서도 제목이 읽히게 만든다.
- AI로 제작한 썸네일은 공식 화면이나 사실 근거를 대신하지 않는다. 본문의 공식 캡처는 해당 설명 아래에 별도로 유지한다.

- 같은 이모티콘을 한 글에서 반복하지 않는 것을 기본으로 한다.

### 네이버 캐릭터 스티커

문자형 이모지와 네이버 캐릭터 스티커는 서로 다른 요소다. 캐릭터 스티커는 이미지를 복사하지 않고 스마트에디터 ONE의 `스티커` 컴포넌트에서 삽입한다.

- 기본 도구 막대에서 `스티커`를 누르고 오른쪽 패널의 캐릭터를 본문으로 끌어다 놓는다.
- 기본 제공 또는 이미 보유한 스티커는 추가 결제 없이 사용한다.
- 더 필요한 스티커는 패널의 `구매하기`를 눌러 네이버 OGQ 마켓에서 유료·무료 상품을 추가한다.
- 구매 후 편집기의 스티커 패널을 새로 고쳐 목록에 반영한다.
- 스티커는 도입의 친근한 전환, 직접 해보는 단계, 사진 촬영 안내, 체크 포인트, 마무리 반응처럼 실제 문맥이 맞는 곳에 적극 활용한다.
- 개수의 상한이나 권장 수량을 두지 않는다. 각 스티커가 도입·설명·행동·확인·전환·마무리 중 분명한 역할을 가질 때 필요한 만큼 사용한다.
- 많이 사용하는 것 자체를 목표로 삼지는 않으며, 같은 감정·같은 기능을 반복하거나 정보보다 스티커가 먼저 보이면 줄인다.
- 정책·세금·피해·질병의 핵심 근거 바로 옆에는 장난스러운 스티커를 두지 않는다.
- 같은 캐릭터를 매 글 반복하지 않고, 공식 화면·표·사진의 정보 전달을 방해하지 않도록 독립된 빈 문단 사이에 배치한다.
- 외부 블로그에 표시된 스티커 이미지를 캡처·복사해 재사용하지 않는다. 편집기에서 제공되거나 해당 계정이 정식 보유한 스티커만 사용한다.

### 기존 브링이슈 글 연결

- 원고 작성 전에 공개된 기존 글의 제목·주제·URL을 검색한다.
- 현재 글을 읽은 다음 독자가 실제로 궁금해할 질문에 답하는 글만 1~2편 고른다.
- 단순히 같은 카테고리라는 이유로 연결하지 않는다. `현재 문제 → 다음 판단` 또는 `총론 → 세부 행동` 관계가 있어야 한다.
- 관련 글이 아직 예약·비공개 상태라면 연결하지 않는다. 실제 공개 URL을 다시 열어 확인한 뒤에만 넣는다.
- 본문 끝 URL 목록 대신, 연결 이유를 한 문장으로 먼저 쓰고 바로 아래에 네이버 링크 카드를 삽입한다.
- 링크 카드 뒤에는 빈 문단 1개를 둔다. 주 CTA와 경쟁하지 않도록 관련 글 명령형 문구는 한 번만 사용한다.

### 실제 입력 순서

1. 제목을 입력하고 모바일 앞부분에서 핵심 검색어가 잘리지 않는지 확인한다.
2. 본문 전체를 붙여 넣고 나눔고딕 19·줄간격 180%를 먼저 적용한다.
3. 도입과 일반 설명은 가운데 정렬하고, 표·긴 체크리스트·비교 목록만 왼쪽 정렬한다.
4. 주요 소제목을 24·굵게로 바꾸고 필요한 곳에만 이모지를 남긴다.
5. 의미 묶음·소제목·구분선·사진·표·인용구·링크의 빈 문단을 위 기준대로 조정한다.
6. 형광펜 2~3곳, 밑줄 2~3곳, 인용구 0~1곳이 서로 겹치지 않는지 확인한다.
7. 실제 화면을 관련 설명 바로 아래에 넣고 캡션 15·회색·가운데 정렬을 적용한다.
8. 공식 링크와 관련 글을 설명 문장 뒤 링크 카드로 넣는다.
9. 글의 분위기와 기능에 맞는 네이버 캐릭터 스티커를 주요 정보 블록에 나누어 삽입한다.
10. PC와 모바일 미리보기에서 스티커·링크 카드·사진의 잘림, 과도한 공백, 좁은 표, 읽히지 않는 캡처가 없는지 확인한다.

## 반복 시리즈 규칙

- 한 주제는 총론 1편과 세부 질문 3~6편으로 확장할 수 있다.
- 시리즈 라벨과 대표색은 유지하되 제목·도입·결론 문장을 복사하지 않는다.
- 후속 글은 앞 글을 요약하는 대신 독자의 다음 질문 하나를 완결한다.
- 관련 글은 현재 글을 읽은 뒤 자연스럽게 생기는 다음 질문 1~2개만 연결한다.

## 공개 전 QA

### 발행 직전 강제 게이트

- [ ] 발행 버튼을 누르기 직전에 확정된 모든 브링이슈 매뉴얼을 현재 파일에서 다시 읽었다.
- [ ] 해당 원고·공식 캡처·네이버 표·정렬·여백·구분선·형광펜·밑줄·이모티콘을 매뉴얼과 다시 대조했다.
- [ ] 불일치 항목을 먼저 수정했고 재검수 결과를 발행 관리표 또는 브리프에 기록했다.
- [ ] 위 세 항목 중 하나라도 완료되지 않으면 예약발행·즉시발행 버튼을 누르지 않는다.

- [ ] 제목의 질문을 도입 20% 안에서 해결했다.
- [ ] 제목 라벨·숫자·이모지는 실제 정보와 시리즈 목적이 있을 때만 사용했다.
- [ ] 이모티콘은 `blogpeople` 실제 관찰 목록에서 주제 역할에 맞는 문자를 골랐고 같은 문자를 반복하지 않았다.
- [ ] 캐릭터 스티커는 네이버 편집기 제공 또는 해당 계정이 정식 보유한 항목만 사용했고, 도입·단계·체크·마무리의 역할과 문맥이 맞는다.
- [ ] 공개된 기존 브링이슈 글을 검색했고, 직접 이어지는 글이 있으면 실제 공개 URL을 확인해 링크 카드 1~2개로 연결했다.
- [ ] 도입 세 문단 안에서 독자 장면·결론·확인 순서가 보인다.
- [ ] 표는 네이버 자체 표다.
- [ ] 표·인용구·구분선·이모지를 정해진 개수를 채우려고 억지로 넣지 않았다.
- [ ] 본문 19·소제목 24·캡션 15와 줄간격 180%를 실제 편집기에서 확인했다.
- [ ] 의미 묶음과 사진·표·인용구·링크 전후의 빈 문단이 1개이며, 연속 빈 문단이 없다.
- [ ] URL 원문을 늘어놓지 않고 설명 문장 뒤 네이버 링크 카드로 넣었다.
- [ ] 사진이 문장을 끊지 않는다.
- [ ] 모든 사진에 대표·근거·행동·비교·예외 중 하나의 역할이 있다.
- [ ] 모든 사진의 글자가 모바일에서 읽힌다.
- [ ] 사진 전후 설명이 반복되지 않는다.
- [ ] 관련 없는 이미지와 출처 덤프가 없다.
- [ ] 형광펜·밑줄·이모티콘이 제한 범위 안이다.
- [ ] 전체공개·검색허용·카테고리·주제·태그를 확인했다.
- [ ] 공개 URL에서 PC와 모바일 화면을 다시 확인했다.
